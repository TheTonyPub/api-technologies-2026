# ДЗ 2. Контракты взаимодействия

## Проект: Система противодействия мошенничеству (Антифрод)

**Описание кейса:**
Спроектировать информационную систему противодействия мошенничеству.

**Основные пользователи:** клиенты банка и сотрудники отдела безопасности.
**Суть системы:** анализирует историю операции клиента и применяет модель машинного обучения для выявления подозрительных действий.

### Внешние потребители:
1.  **Автоматизированная банковская система (АБС)** — Главная система банка, где хранится вся информация. Передает нам историю клиента.
2.  **Команда аналитиков** — Разрабатывают и обучают модели машинного обучения. Разрабатывает и передает новые версии моделей.
3.  **Внешние источники данных (для Online-витрины)** — Раскрывают данные о клиенте. Передают информацию о возрасте, пол, место проживания итд.
4.  **Клиент банка** — Инициирует транзакции, которые проверяются АБС от мошенничества. Через него передаются данные об операциях. Примечание: является косвенным потребителем, взаимодействует с АБС, а не с антифрод-системой напрямую.

### Взаимодействие с внешним миром:
1.  АБС фиксирует событие транзакции и отправляет его в систему.
2.  Система обращается к Online-витрине для того, чтобы узнать историю клиента (частота операций, переводы).
3.  Система вызывает Внешние источники данных (если требуется информация, которой нет, например, возраст или геолокация).
4.  Система применяет модель машинного обучения.
5.  Система возвращает вердикт (`1` — подтверждено, `0` — отклонено) обратно в АБС.
6.  Клиент банка получает результат операции через интерфейс банка.

### Обоснование выбора технологий:
*   **Python:** Используется для работы Ml-модели ('Ml-сервис'), получения дополнительных данных о клиенте ('Enrichment') и организации процессов регулярной загрузки данных ('ETL'). Имеет все необходимые библиотеки для работы с ИИ и анализа данных.
*   **gRPC:** Быстрая бинарная сериализация данных, строгая типизация. Расходы на передачу данных в разы ниже, чем у REST\JSON. Основной протокол для межсервисного взаимодействия внутри антифрод-системы ('Gateway', 'Enrichment', 'Features', 'ml', 'Rules'). Позволяет сэкономить ценные миллисекунды.
*   **REST API:** Обеспечивает гибкость интеграции банковской системой (АБС) с минимальной задержкой.
*   **Redis 7:** Данные хранятся прямо в оперативной памяти, что обеспечивает мгновенный доступ (1-3 миллисекунды). Используется как быстрая витрина данных. В Redis заранее загружена готовая статистика по клиенту, которую система мгновенно подтягивает во время проверки.
*   **ClickHouse 24:** Высокая скорость чтения и агрегации больших объемов исторических данных, эффективное сжатие данных. Хранение полной истории транзакций клиентов. Используется для формирования аналитической витрины, пересчета агрегаторов и обучения новых ML-моделей.
*   **S3 / MinIO:** Удобное и надежное хранение бинарных артефактов любого размера. Хранение версий обученных ML-моделей, выгружаемых аналитиками и подгружаемых ML-сервисом.
*   **Kafka:** Высокая пропускная способность, возможность асинхронной обработки событие без блокировки основного потока транзакции. Отвечает за сохранение истории транзакций.
*   **Airflow:** Удобный инструмент для мониторинга, автоматизации пакетов обработки данных.
