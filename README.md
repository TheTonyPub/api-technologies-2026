## Описание кейса
Спроектировать информационную систему противодействия мошенничеству  
## Взаимодействие сервисов
Система представляет собой сервис для автоматизированной проверки банковских транзакций на мошенничество. Основные пользователи - клиенты банка и сотрудники отдела безопасности. Система анализирует историю операции клиента и применяет модель машинного обучения для выявления подозрительных действий.

### Внешние потребители:

1. **Автоматизированная банковская система(АБС)**
Главная система банка, где хранится вся информация. Передает нам историю клиента.

2.  **Команда аналитиков**
Разрабатывают и обучают модели машинного обучения. Разрабатывает и передает новые версии моделей.
 
3.  **Внешние источники данных (для Online-витрины)**
Раскрывают данные о клиенте. Передают информацию о возрасте, пол, место проживания итд.

### Взаимодействие с внешним миром

1.  АБС фиксирует событие транзакции и отправляет его в систему.
2.  Система обращается к Online-витрине для того, чтобы узнать историю клиента(частота операций, переводы).
3.  Система вызывает Внешние источники данных (если требуется информация, которой нет, например, возраст или геолокация).
4.  Система применяет модель машинного обучения.
5.  Система возвращает вердикт (`1` — подтверждено, `0` — отклонено) обратно в АБС.
6.  Клиент банка получает результат операции через интерфейс банка.

## Обоснование выбора технологий

### 1. Языки программирования 

* **Python:**
   * **Роль в проекте:** Используется для работы Ml-модели ('Ml-сервис'), получения дополнительных данных о клиенте ('Enrichment') и организации процессов регулярной загрузки данных ('ETL')
   * **Почему выбрали:** Python имеет все необходимые библиотеки для работы с искусственным  интеллектом и анализом данных 

---

### 2. Протоколы взаимодействия 

* **gRPC:**
   * Быстрая бинарная сериализация данных, строгая типизация через '.proto' - файлы. Расходы на передачу данных в разы ниже, чем у REST\JSON 
   * Основной протокол для межсервисного взаимодействия внутри антифрод-системы ('Gateway', 'Enrichment', 'Features', 'ml', 'Rules'). Позволяет сэкономить ценные миллисекунды

* **REST API:**
   * Обеспечивает гибкость интеграции банковской системой (АБС) с минимальной задержкой 

---

### 3. Базы данных и хранилища 

* **Redis 7:**
   * Данные хранятся прямо в оперативной памяти, что обеспечивает мгновенный доступ (1-3 миллисекунды)
   * Используется как быстрая витрина данных. В Redis заранее загружена готовая статистика по клиенту, которую система мгновенно подтягивает во время проверки 

* **S3 / MinIO:**
   * Удобное и надежное хранение бинарных артефактов любого размера 
   * Хранение версий обученных ML-моделей, выгружаемых аналитиками и подгружаемых ML-сервисом
* **Data Lake:**
   * Хранилище исходных исторических данных. Служит источником для наполнения Online-витрины и для переобучения ML-моделей. Мы читаем оттуда данные для аналитики и формирования признаков.

---

### 4. Ассинхронная обработка и фоновые процессы 

* **Airflow:**
   * Удобный инструмент для мониторинга, автоматизации пакетов обработки данных
   * Регулярная загрузка исторических данных из АБС, расчет агрегатов и обновление данных в 'Redis' и 'ClickHouse'
