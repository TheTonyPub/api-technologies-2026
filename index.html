Практическая работа 4. Выбор стиля взаимодействия с API

Взаимодействуйте с четырьмя сервисами, имитирующими ML-инференс: REST сразу возвращает предсказание, gRPC демонстрирует четыре типа вызовов для транзакций, WebSocket обрабатывает поток измерений в одном соединении, а event-driven API передаёт задание отдельному обработчику.

Модели используют простые детерминированные правила. Цель — исследовать протоколы: что отправляет клиент, когда получает ответ и где проходит граница между сервисами.

Что понадобится

  • Команды рассчитаны на macOS, Linux или WSL.
  • cURL для HTTP-запросов.
  • grpcurl для gRPC (Homebrew: brew install grpcurl).
  • websocat для WebSocket (Homebrew: brew install websocat).

Эндпоинты серверного стенда

Если включена Basic Auth, получите имя пользователя и пароль у преподавателя. Выполните настройку ниже до начала записи терминала: пароль вводится скрыто.

printf 'Basic Auth user: '; IFS= read -r BASIC_USER
printf 'Basic Auth password: '; IFS= read -rs BASIC_PASS; printf '\n'
BASIC_HEADER="Authorization: Basic $(printf '%s' "$BASIC_USER:$BASIC_PASS" | base64 | tr -d '\r\n')"
unset BASIC_PASS

В macOS/Linux/WSL запишите терминальный сеанс командой script -q seminar04.log, завершите его командой exit. Не включайте в журнал токены, пароли, Basic Auth credentials или содержимое .env; удалите их также из подробного вывода перед сдачей.

Не выводите и не передавайте $BASIC_HEADER. Не включайте set -x и не используйте curl -v или grpcurl -v при записи. Если Basic Auth выключена, уберите -H "$BASIC_HEADER" из команд.

1. REST: немедленный ответ

Передайте срок обслуживания клиента, месячные расходы и число обращений в поддержку. Ответ содержит оценку риска risk_score и метку risk_label.

Сервер — успешный запрос

curl -i -X POST https://seminar04.dataprosvet.ru/rest/v1/predict \
  -H "$BASIC_HEADER" -H 'Content-Type: application/json' \
  -d '{"tenure_months":18,"monthly_spend":240.5,"support_tickets":2}'

Запишите HTTP-код и оба поля результата. Предсказание приходит в ответе на тот же вызов.

Сервер — запрос с ошибкой (нет monthly_spend)

curl -i -X POST https://seminar04.dataprosvet.ru/rest/v1/predict \
  -H "$BASIC_HEADER" -H 'Content-Type: application/json' \
  -d '{"tenure_months":18,"support_tickets":2}'

Обязательное поле monthly_spend пропущено. Запишите статус и тело ошибки. Документация: https://seminar04.dataprosvet.ru/rest/docs.

2. gRPC: четыре типа вызовов

gRPC использует HTTP/2 и protobuf-схемы. В исходной схеме ключевое слово stream у запроса или ответа задаёт тип вызова. Reflection позволяет grpcurl обнаружить все методы без скачивания proto-файла. О четырёх типах вызовов читайте в официальной документации gRPC и статье из задания. Все методы используют одну детерминированную оценку риска транзакции.

Сравните схему со сгенерированными модулями transaction_pb2.py (описания protobuf-сообщений) и transaction_pb2_grpc.py (клиентский stub и серверная регистрация методов). Они создаются из .proto, а не редактируются вручную.

Выполните unary, server streaming, client streaming и bidirectional streaming. Сравните число сообщений в запросе и ответе, момент получения результата и идентификаторы транзакций.

Сервер — reflection и успешный запрос

grpcurl -H "$BASIC_HEADER" seminar04.dataprosvet.ru:443 list
grpcurl -H "$BASIC_HEADER" seminar04.dataprosvet.ru:443 describe seminar04.v1.TransactionInference
grpcurl -H "$BASIC_HEADER" -d '{"transactions":[{"id":"tx-1","amount":125.5,"international":false,"merchant_risk":0.2},{"id":"tx-2","amount":980,"international":true,"merchant_risk":0.8}]}' \
  seminar04.dataprosvet.ru:443 seminar04.v1.TransactionInference/PredictBatch

В predictions сопоставьте каждый результат с идентификатором транзакции.

Сервер — запрос с ошибкой (пропущено id)

grpcurl -H "$BASIC_HEADER" -d '{"transactions":[{"amount":125.5,"international":false,"merchant_risk":0.2}]}' \
  seminar04.dataprosvet.ru:443 seminar04.v1.TransactionInference/PredictBatch

У обязательного поля id нет значения. Запишите gRPC status и сообщение; сравните с HTTP validation error REST.

Server streaming: один пакет, несколько ответов

Сервер:

grpcurl -H "$BASIC_HEADER" -d '{"transactions":[{"id":"tx-1","amount":125.5,"international":false,"merchant_risk":0.2},{"id":"tx-2","amount":980,"international":true,"merchant_risk":0.8}]}' \
  seminar04.dataprosvet.ru:443 seminar04.v1.TransactionInference/PredictBatchStream

Сравните вывод с unary: здесь приходят отдельные сообщения TransactionPrediction, каждое со своим id.

Client streaming: несколько транзакций, одна сводка

Сервер:

printf '%s\n' \
  '{"id":"tx-1","amount":125.5,"international":false,"merchant_risk":0.2}' \
  '{"id":"tx-2","amount":980,"international":true,"merchant_risk":0.8}' |
  grpcurl -H "$BASIC_HEADER" -d @ seminar04.dataprosvet.ru:443 seminar04.v1.TransactionInference/AggregateTransactions

grpcurl -d @ читает отдельные JSON-сообщения из stdin. Запишите поля ответа transactionCount, averageRisk и highRiskCount. Сводка приходит после завершения клиентского потока. В .proto эти поля записаны в snake_case; protobuf JSON выводит имена в camelCase.

Bidirectional streaming: сообщения в обе стороны одного вызова

Сервер:

grpcurl -H "$BASIC_HEADER" -d @ seminar04.dataprosvet.ru:443 seminar04.v1.TransactionInference/PredictLive

Введите в открытом вызове по одной строке, нажимая Enter после каждой; завершите ввод Ctrl+D:

{"id":"tx-live-1","amount":125.5,"international":false,"merchant_risk":0.2}
{"id":"tx-live-2","amount":980,"international":true,"merchant_risk":0.8}

Сопоставьте ответы по id и отметьте, появляется ли ответ до завершения ввода. Сравните обмен с WebSocket. Во всех потоковых методах действуют те же правила валидации транзакции, что и в unary.

3. WebSocket: поток предсказаний

Сервис принимает измерения температуры, вибрации и оборотов двигателя. Отправьте несколько сообщений в одном открытом соединении и получите оценку anomaly_score и флаг anomaly для каждого.

Сервер — откройте защищённое соединение

websocat -t -H="$BASIC_HEADER" wss://seminar04.dataprosvet.ru/stream/v1/live

После подключения введите по очереди две строки, нажимая Enter после каждой:

{"temperature":65,"vibration":0.12,"rpm":1400}
{"temperature":112,"vibration":0.91,"rpm":2800}

После каждой строки найдите ответ с anomaly_score и anomaly. Сравните время ответа в открытом соединении с REST round trip.

Сообщение с ошибкой

Не закрывая соединение, введите ошибочную строку:

{"temperature":65,"rpm":1400}

Поле vibration пропущено. Сервис возвращает сообщение {"error":"invalid_telemetry","detail":"..."} и оставляет соединение открытым. Введите ещё одно корректное сообщение, получите новое предсказание и завершите сеанс Ctrl+D. Сравните задержку ответа в уже открытом WebSocket-соединении с REST-запросом.

4. Event-driven: задание для отдельного worker

HTTP endpoint принимает пакет и отвечает 202 Accepted с job_id. Затем event API публикует запрос в NATS JetStream. Отдельный worker выполняет нормализацию и inference и публикует результат. Код 202 означает, что задание принято, но ещё не обязательно завершено.

Сервер — успешное задание и получение статуса

curl -i -X POST https://seminar04.dataprosvet.ru/events/v1/jobs \
  -H "$BASIC_HEADER" -H 'Content-Type: application/json' \
  -d '{"records":[{"customer_id":"c-1","monthly_usage":42,"support_tickets":1},{"customer_id":"c-2","monthly_usage":105,"support_tickets":4}]}'

Сохраните job_id из ответа и подставьте его:

JOB_ID='вставьте-job_id-из-ответа'
curl -i -H "$BASIC_HEADER" "https://seminar04.dataprosvet.ru/events/v1/jobs/$JOB_ID"

Если статус ещё pending, повторите GET через короткий интервал. После завершения сохраните результаты.

Документация: https://seminar04.dataprosvet.ru/events/docs.

Сервер — неверное тело

curl -i -X POST https://seminar04.dataprosvet.ru/events/v1/jobs \
  -H "$BASIC_HEADER" -H 'Content-Type: application/json' -d '{}'

В теле нет обязательного списка records; запишите ошибку валидации.
